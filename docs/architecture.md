# Архитектура

Next.js 14 App Router на TypeScript strict. Серверные секции рендерят содержание и SEO. Клиентские компоненты отвечают за программу, форму, карту, аналитику и анимацию. Tailwind 3 использует общие токены и светлую тему HeroUI. Кнопки заявки, бейдж расписания и аккордеон FAQ используют отдельные пакеты HeroUI 2. Провайдер задаёт локаль ru-RU. Framer Motion и Lenis учитывают reduced motion. Leaflet подгружается вблизи секции карты и работает с OpenStreetMap.

| Путь                 | Назначение                                     |
| -------------------- | ---------------------------------------------- |
| app/                 | HTML, метаданные, стили, POST /api/lead        |
| components/ui/       | Кнопка, бейдж и аккордеон                      |
| components/shared/   | Навигация, общая секция, CTA, анимация, скролл |
| components/sections/ | Секции маршрута и слой Leaflet                 |
| content/             | Локации, расписание, дни, цены, фотографии и FAQ |
| lib/                 | Типы, схема заявки, аналитика, классы          |
| public/              | Фотографии и шрифты                            |
| docs/                | Документация проекта                           |

Day хранит заголовок и описания остановок. Location содержит ID, область, координаты и необязательные фото. ScheduleSlot хранит дату, длительность, остаток мест и признак демо. Tariff содержит цену, единицу расчёта и состав. FAQItem хранит вопрос и ответ. Lead выводится из схемы Zod.

POST /api/lead принимает JSON с именем, телефоном, форматом, количеством, продолжительностью, целью, датой, выбранными локациями, комментарием, согласием и пустым honeypot. Ответы 400 и 413 означают ошибку ввода, 503 — отсутствие конфигурации, 502 — сбой Telegram. В деморежиме возвращается demo=true. Реальная отправка использует Telegram Bot API. CRM можно подключить отдельным адаптером на том же серверном входе.

Metadata содержит язык, заголовок, описание и OG. Разметка TouristTrip доступна на странице, LocalBusiness включается при ORGANIZER_NAME. Слоты расписания перепроверяются при серверном рендере.

После согласия на аналитику события cta_click, form_submit, scroll_depth и map_point_click передаются через CustomEvent. При подключённом скрипте Яндекс Метрики и NEXT_PUBLIC_METRIKA_ID они также передаются как цели. Выбор хранится в localStorage, его можно изменить в подвале. Счётчик подключается владельцем отдельно.

Сборка запускается из корня репозитория. Серверная версия работает на Node.js или Vercel. Настройки NEXT_PUBLIC_SITE_URL, NEXT_PUBLIC_METRIKA_ID, ORGANIZER_NAME, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID и LEAD_DEMO. Секреты задаются в окружении сервера. Статическая сборка GitHub Pages публикуется из out/. Для реального трафика нужен утверждённый процесс обработки лидов и ограничение частоты запросов на уровне хостинга.
