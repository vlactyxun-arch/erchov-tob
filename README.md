# Тобольск глазами Ершова

Одностраничный туристический маршрут на русском языке. В архиве исходный код, данные, материалы и проектная документация.

## Запуск

Требуется Node.js 22 и npm. Команды запускаются из корня репозитория:

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Для демонстрации формы скопируйте .env.example в .env.local. При LEAD_DEMO=true форма валидирует заявку без отправки.

```sh
npm run lint
npm run build
npm start
```

Для запуска приёма заявок задайте TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID, проверьте права бота в чате и отключите LEAD_DEMO. Для индексации задайте абсолютный NEXT_PUBLIC_SITE_URL. ORGANIZER_NAME включает разметку LocalBusiness. До публикации замените временные фото и заполните сведения об организаторе и обработке данных.

Проект находится в корне репозитория и архива. На сервере с Node.js установите зависимости через `npm ci`, соберите проект через `npm run build` и запустите через `npm start`. Для статического хостинга соберите проект с `NEXT_PUBLIC_GITHUB_PAGES=true` и загрузите содержимое `out/` в каталог сайта. Если сайт размещён в подпапке, задайте её через `NEXT_PUBLIC_BASE_PATH` перед сборкой.

## GitHub Pages

Workflow .github/workflows/pages.yml собирает статическую версию при push в main. В настройках Pages источник публикации должен быть GitHub Actions. Форма записи находится на лендинге.

Для отправки заявок с Pages задайте переменную репозитория GitHub Actions `NEXT_PUBLIC_LEAD_ENDPOINT` с публичным HTTPS-адресом серверного `/api/lead`. На сервере API задайте `LEAD_ALLOWED_ORIGIN=https://vlactyxun-arch.github.io` и настройте параметры Telegram. При локальной статической сборке адрес API можно задать в окружении под тем же именем. Пока адрес API не задан, форма показывает, что отправка недоступна. Серверная сборка по умолчанию использует свой `/api/lead`.

## Структура

- app/ — страница, стили и API заявок
- components/ — секции, общие компоненты и элементы интерфейса
- content/ — данные маршрута в JSON
- lib/ — типы, валидация и события аналитики
- public/ — локальные материалы
- docs/ — требования, архитектура, дизайн, задачи и решения
